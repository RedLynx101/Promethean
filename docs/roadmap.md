# Where Promethean goes next

[← Promethean](../README.md)

The current release proves a bounded local loop: diagnose, compare, revise, execute and inspect. Expansion should preserve the ability to explain why a simpler implementation is sufficient and what evidence would change that conclusion.

| Direction             | Useful next capability                                                  | Evidence required before calling it supported                                               |
| --------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| More workflow recipes | Add repeatable operational tasks beyond the three installed examples    | Real deterministic baseline, explicit input/output contract and fresh task cases            |
| Richer evidence       | Import a user's documents with source versions and retrieval provenance | Permission boundaries, deletion behavior, grounded-answer and absent-answer cases           |
| External connectors   | Turn an approved prepared action into a real provider operation         | Provider authorization, idempotency/reconciliation, ambiguous-outcome and recovery tests    |
| Scheduling            | Manual workflows become scheduled or event-triggered jobs               | Trigger deduplication, missed-run behavior, cancellation and restart evidence               |
| Broader construction  | Turn supported process elements into reviewed executable patches        | Typed operations, preserved constraints and unaffected steps, bounded graph validation      |
| Shared workspaces     | Collaborate on briefs, versions and approvals                           | Identity, tenant isolation, role-bound approval, retention and deployment validation        |
| Larger evaluations    | Compare architectures across varied tasks and language                  | Held-out cases, uncertainty/escalation behavior, failure analysis and repeated measurements |

These are expansion directions, not features already delivered. A marketplace, billing and unrestricted connectors can wait until the core workflow and its operational guarantees justify them.
