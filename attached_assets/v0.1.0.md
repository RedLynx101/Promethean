# Promethean Studio — v0.1.0 (MVP)

The Promethean Studio MVP is complete and fully working. Below is a detailed breakdown of everything that was built.

## Architecture

The project is a pnpm monorepo with two main artifacts:

- **Frontend** (`artifacts/promethean`) — React + Vite PWA with ARWES-inspired sci-fi dark theme, React Flow visual editor, and Recharts data visualizations.
- **Backend** (`artifacts/api-server`) — Express.js API server using Drizzle ORM with PostgreSQL, and a 4-agent AI pipeline powered by GPT-4o-mini via Replit AI integration.
- **Shared libraries** (`lib/`) — Database schema (`lib/db`), OpenAPI spec (`lib/api-spec`), and auto-generated React Query hooks + Zod schemas via Orval (`lib/api-client-react`).

## Database Schema

PostgreSQL with Drizzle ORM. Six core tables:

- **workflows** — Stores workflow metadata, current pipeline phase (`wizard`, `decompose`, `select`, `orchestrate`, `govern`, `deployed`), status, and JSONB columns for `nodes` and `edges` representing the visual graph.
- **workflow_versions** — Version history for deployed workflows, tracking changes between versions with a changelog field.
- **executions** — Individual runs of a workflow, including status (`running`, `completed`, `failed`), total cost, and latency.
- **execution_steps** — Detailed per-step logs within an execution, capturing input/output payloads, LLM call details, and tool invocations.
- **alerts** — Monitoring alerts (drift detection, high latency, cost threshold, error spike) with status tracking (`active`, `acknowledged`, `resolved`).
- **templates** — Pre-built workflow templates with domain tags, star ratings, and usage counts.

## API Routes

Full RESTful API at `/api`:

- **`/api/workflows`** — CRUD for workflow configurations (list, create, get by ID, update, delete).
- **`/api/pipeline/start`** — Kicks off the 4-stage AI pipeline starting with decomposition.
- **`/api/pipeline/:id/approve`** — Advances the workflow to the next pipeline phase (Decompose → Select → Orchestrate → Govern → Deployed).
- **`/api/pipeline/:id/reject`** — Re-runs the current phase with user-provided feedback.
- **`/api/executions`** — Triggers and lists workflow execution history.
- **`/api/templates`** — Lists available templates and supports one-click deploy to create a new workflow from a template.
- **`/api/alerts`** — Lists alerts and provides acknowledge/resolve endpoints.
- **`/api/dashboard`** — Aggregates KPI stats (total executions, success rate, average latency, total cost) and 14-day activity data for the Command Center charts.

## AI Agent Pipeline

Four sequential agents, each making a distinct OpenAI call with a carefully crafted system prompt:

1. **Decomposition Agent** — Takes the user's workflow description and breaks it into discrete substeps, generating preliminary React Flow nodes with names, descriptions, and suggested input/output schemas.
2. **System Selection Agent** — Analyzes each node and classifies it on the L0–L5 automation spectrum (L0 Deterministic → L5 Multi-Agent). Must start at L0 and justify upward movement. Produces confidence scores and rationale for each classification.
3. **Orchestration Agent** — Adds edges between nodes, configures tool bindings, sets conditions and error handling, and defines the execution flow.
4. **Governance Agent** — Generates governance configuration: logging levels, drift detection thresholds, alert channel settings, and guardrail rules.

Each phase has a **human-in-the-loop gate** — the user reviews the agent's output in the visual editor and can approve, edit and approve, regenerate with feedback, or reject.

## Frontend Pages

Five main views, all using the ARWES-inspired sci-fi dark theme:

### Command Center (Dashboard)
- KPI metrics cards: total executions, success rate, average latency, total cost
- Execution timeline area chart with 14-day history (Recharts)
- Live alert feed with Acknowledge/Resolve controls
- Workflow fleet grid showing each workflow with status pulse indicators and success rate bars

### Workflow Wizard
- 4-step intake form:
  1. Describe the workflow (name and natural-language description)
  2. Set constraints (domain, budget limit, latency target, risk tolerance)
  3. Configure governance (human oversight level, guardrails)
  4. Review the brief and launch the AI pipeline

### Workflow Editor
- React Flow visual canvas with custom color-coded nodes for all 8 node types:
  - L0 (Deterministic): green `#4CAF50`
  - L1 (Rules Engine): blue `#2196F3`
  - L2 (ML Model): purple `#9C27B0`
  - L3 (Single Agent): orange `#FF9800`
  - L4 (Multi-Agent): red `#F44336`
  - L5 (Autonomous): pink `#E91E63`
  - Human Gate: gray `#607D8B`
  - Trigger: brown `#795548`
- Each node displays: name, system level badge, confidence score (green ≥80%, yellow 60-79%, red <60%), status indicator, tool tags, and an expand button for rationale
- Phase tracker bar at the top showing pipeline progress
- Human-gate approval controls (Approve / Edit & Approve / Regenerate / Reject) appear when a phase needs review

### Template Library
- 6 pre-built templates:
  1. CRM Lead Qualification
  2. Compliance Memo Generation
  3. Code Review Pipeline
  4. Cybersecurity Incident Response
  5. Customer Support Triage
  6. Data Quality Check
- Filterable by domain, with star ratings and usage counts
- One-click deploy to create a new workflow from any template

### Workflow Detail
- Execution metrics summary
- Bar chart of recent run times color-coded by success/failure
- Scrollable execution log with durations
- Version history

## Auto-Seeding

The server automatically seeds the database on startup with:
- 6 sample workflow templates across different domains
- Mock execution data for dashboard visualization

## Out of Scope (deferred beyond v0.1.0)
- Actual production execution of user workflows (simulation only)
- External observability (Langfuse/Helicone — simulated metrics)
- MCP server exposure and A2A protocol
- Inngest cron/event triggers (manual trigger only)
- Export to LangGraph Python / n8n format
- ChromaDB vector memory for template matching
- User authentication
